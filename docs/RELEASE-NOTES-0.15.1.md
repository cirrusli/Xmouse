# Xmouse 0.15.1

修复手势轨迹卡住、松键后不执行也不消失，且后续手势无法开始的问题。

原实现依赖唯一的钩子松键事件结束候选状态；该事件遗漏后，30 秒恢复与前台切换恢复又会因为“仍在绘制”而跳过。松键时获取状态锁失败的分支也只清除原子门控，留下候选轨迹和显示层，造成状态不一致。

现在原始鼠标输入提供独立的释放信号，钩子和 UI 线程分别在绘制期间启动 100 ms 看门狗。释放信号到达但正常结束未完成时，保留 150 ms 宽限后取消并清理候选状态；异常手势最长 15 秒，随后恢复钩子。正常松键和恢复均停用看门狗。原始输入只提取按钮释放标记，空闲时不解析数据，不记录坐标。

每笔手势使用独立编号，迟到的绘制/结束消息无法影响下一笔。恢复只取消异常轨迹，不执行其动作或补发右键；原因记录在 `xmouse.log` 的“手势恢复”行，有效绘制计为一次取消。

本机探针确认：被钩子消费的按下事件不会可靠反映到 `GetAsyncKeyState`，因此本修复没有依赖它推断松键。原始鼠标监听采用 [Raw Input](https://learn.microsoft.com/en-us/windows/win32/inputdev/about-raw-input)，并保留对 [低级钩子被系统静默移除](https://learn.microsoft.com/en-us/windows/win32/winmsg/lowlevelmouseproc) 的超时恢复。

新增故障注入测试实际运行 Win32 消息计时器：故意省略正常松键路径，仅发送独立释放信号，确认关闭轨迹消息送达、候选状态清空、计时器停止，且不执行动作或重放鼠标输入。另覆盖锁竞争重试、旧会话隔离、超时、左右键交换和时间戳回绕。

2026-10-31 验证：HOK-012～014 的自动回归和全部 63 项常规测试、格式、Clippy、Release 构建通过。修复版部署后，日志记录到 ←/→、↑、C、V、L 的连续正常动作，用户实测确认“轨迹消失，手势恢复正常”。20 秒空闲抽样 CPU 增量为 0、私有内存约 2.57 MiB；该短样本不替代 5 分钟性能验收。
