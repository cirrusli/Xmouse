# Xmouse 代码现状与后续迭代（2026-11-01）

## 当前基线

- 平台与交付：Windows 10/11 x64；Rust 2024 + `windows`/`windows-sys`、Win32/GDI、SQLite；便携单 EXE，SQLite 3.54.1 静态链接，无 WebView、运行时服务或应用内联网。
- 当前开发版本：0.16.1。`scripts/quality.ps1` 的常规测试门禁为 69 项，另有 1 项会改写用户剪贴板的交互测试，默认不运行。0.16.0 main 的 MSVC 实测行覆盖率为 28.56%，函数覆盖率为 42.45%；门禁仍为 24%，该数字不代表 0.16.1 重新测量的结果。
- 主要能力：九种内置手势及个人样本、有限安全动作映射、前台/全屏/进程保护、托盘与管理员自启、文本和图片历史、来源/类型/关键词筛选、置顶、搜索高亮、自动粘贴、浅/深色 UI，以及按本地日/月/年聚合的手势统计页。
- 既有修复：`Win+Ctrl+←/→` 的方向键扫描码显式带 `KEYEVENTF_EXTENDEDKEY`；钩子放行系统标记为注入的鼠标输入。0.15.1 部署后用户连续实测 ←/→、↑、C、V、L，确认轨迹结束和手势动作恢复正常；仍不能单凭 `SendInput` 的成功返回值推断所有目标应用均已响应。
- Git 回溯定位：`20a658d` 将键盘事件切换到扫描码时引入了桌面切换回归。0.15.0 起每次完成绘制的手势有一条不含坐标/内容的摘要日志和独立 SQLite 事件，便于区分识别结果、动作提交和窗口实际响应。
- 0.15.1 修复松键遗漏后轨迹常驻：原始鼠标释放监听、双线程会话看门狗和带编号的轨迹消息共同结束异常状态；故障注入覆盖原生计时器、锁竞争和旧会话隔离。下一步仍应继续抽离完整触发状态机，扩大目标窗口与真实硬件兼容性回归。
- 0.15.2 为 Steam 增加当前窗口标准关闭兼容；0.16.0 完成单 EXE、键盘导航/控件语义基础和可配置应用关闭规则。完整 Narrator/DPI 走查仍待完成；组合键、配置导入/导出和动作结果分层未实现。证据与后续验收见 [外部评审](TECHNICAL-REVIEW-2026-10-31.md)。
- 0.16.1 修复有标题栏的普通大窗口被全屏覆盖规则误判；基于 Edge 现场样式/尺寸增加回归，保留无边框全屏保护与独立进程名单。按用户要求不再继续现场 UI 操作，实际游戏兼容仍保留人工验收边界。

## 模块和数据流

| 边界 | 当前实现 | 主要风险 |
| --- | --- | --- |
| `hook.rs` → `gesture.rs` | 专用 `WH_MOUSE_LL` 线程缓存轨迹；动作线程做识别；前台变化/30 秒低频计时器修复钩子 | 状态机仍耦合 Win32 回调，真实右键/注入事件回归主要依赖人工；每个降频轨迹 UI 点有一次堆分配 |
| `actions.rs` → Win32 | 按下时固定目标 HWND；检查焦点后执行键盘/窗口动作 | `SendInput` 返回“已插入”不代表 Shell 或目标应用已处理；桌面切换没有系统状态确认 |
| `clipboard.rs` → `storage.rs` | 事件驱动捕获，后台线程处理，SQLite 保存文本/图片和媒体文件 | 捕获通道无界、突发事件未合并；输入极快时可能积压 |
| `app.rs` → `ui/*` | 单 UI 线程消息循环和自绘组件；页面布局已拆分 | `app.rs` 约 3500 行，消息路由与窗口状态仍集中；历史筛选在 UI 线程同步读库并重建列表 |
| `config.rs` / `autostart.rs` | 版本化 JSON、单实例、当前用户最高权限计划任务 | 任务状态“上次结果 0”不等于进程持续运行；需要独立的驻留/钩子健康判断 |
| `stats.rs` → `ui/stats_view.rs` | 独立 SQLite 事件库；本地日/月/年聚合与排行；页面按事件刷新 | 当前统计只覆盖新版本之后的手势，外部动作实际效果仍无法仅靠 `SendInput` 返回值确认 |

更详细的稳定边界见 [工程架构](ARCHITECTURE.md)，行为编号见 [回归测试计划](REGRESSION-TEST-PLAN.md)。

## 性能判断

架构上没有高频空闲轮询；资源页采样只在可见时启用，历史图片预览线程按需工作；统计页只在打开和收到新事件时查询。本机 0.15.0 的 30 秒空闲样本为平均 CPU 0.0326%、私有内存 2.38 MiB、工作集 14.32 MiB、155 句柄、6 线程（16 逻辑处理器）；这只是小样本，不能证明“已经最优”或满足 5 分钟验收指标。需要分别采集空闲 5 分钟、连续画手势、快速复制、打开 200 条历史时的 CPU、私有内存、工作集、句柄、钩子回调 p99 和 UI 搜索延迟。

已确认的优化候选按收益排序：

1. 历史搜索改为后台查询或限时防抖，并让数据库按类型/来源先过滤；缩略图按可见行加载。当前 `storage::list_filtered` 读取全部行并解码文本/缩略图后在 Rust 中筛词，`app::rebuild_history_with_selection` 在 UI 线程同步调用它。
2. 剪贴板更新通道增加“已有待处理事件”原子门控或有界合并，避免突发复制形成无界队列；保持序号检查，不能遗漏最后一份内容。
3. 轨迹层消息改用有界批量/复用缓冲，减少绘制时的分配；先测钩子 p99，避免为不可见的微优化牺牲可靠性。
4. 钩子 30 秒重装是兼容性保险，不应在缺少真实长期对照测试前直接删除；先记录重装次数、安装失败率与原因，再评估是否调节策略。
