# Xmouse 代码现状与后续迭代（2026-09-26）

## 当前基线

- 平台与交付：Windows 10/11 x64；Rust 2024 + `windows`/`windows-sys`、Win32/GDI、SQLite；便携 EXE + `sqlite3.dll`，无 WebView、运行时服务或应用内联网。
- 当前开发版本：0.14.2。`scripts/quality.ps1` 已通过格式、Release Clippy、51 项常规测试和最终 Release 构建；另有 1 项会改写用户剪贴板的交互测试，默认不运行。代码覆盖率门禁仍是 24%，这是旧 CI 基线，不代表本版重新测量的覆盖率。
- 主要能力：九种内置手势及个人样本、有限安全动作映射、前台/全屏/进程保护、托盘与管理员自启、文本和图片历史、来源/类型/关键词筛选、置顶、搜索高亮、自动粘贴、浅/深色 UI。
- 本轮修复：`Win+Ctrl+←/→` 的方向键扫描码现在显式带 `KEYEVENTF_EXTENDEDKEY`；钩子不再把系统标记为注入的鼠标输入当作手势。独立快捷键在本机双桌面切换成功；模拟右键不再造成重放循环。完整实体鼠标手势仍须验收，不能把 `SendInput` 的成功返回值当成桌面实际切换证明。

## 模块和数据流

| 边界 | 当前实现 | 主要风险 |
| --- | --- | --- |
| `hook.rs` → `gesture.rs` | 专用 `WH_MOUSE_LL` 线程缓存轨迹；动作线程做识别；前台变化/30 秒低频计时器修复钩子 | 状态机仍耦合 Win32 回调，真实右键/注入事件回归主要依赖人工；每个降频轨迹 UI 点有一次堆分配 |
| `actions.rs` → Win32 | 按下时固定目标 HWND；检查焦点后执行键盘/窗口动作 | `SendInput` 返回“已插入”不代表 Shell 或目标应用已处理；桌面切换没有系统状态确认 |
| `clipboard.rs` → `storage.rs` | 事件驱动捕获，后台线程处理，SQLite 保存文本/图片和媒体文件 | 捕获通道无界、突发事件未合并；输入极快时可能积压 |
| `app.rs` → `ui/*` | 单 UI 线程消息循环和自绘组件；页面布局已拆分 | `app.rs` 约 3500 行，消息路由与窗口状态仍集中；历史筛选在 UI 线程同步读库并重建列表 |
| `config.rs` / `autostart.rs` | 版本化 JSON、单实例、当前用户最高权限计划任务 | 任务状态“上次结果 0”不等于进程持续运行；需要独立的驻留/钩子健康判断 |

更详细的稳定边界见 [工程架构](ARCHITECTURE.md)，行为编号见 [回归测试计划](REGRESSION-TEST-PLAN.md)。

## 性能判断

架构上没有高频空闲轮询；资源页采样只在可见时启用，历史图片预览线程按需工作。本机本轮 30 秒空闲样本为 CPU 时间增长 0、私有内存 2.38 MiB、工作集 13.52 MiB、155 句柄、5 线程（16 逻辑处理器）；这只能说明当前状态，不能证明“已经最优”或满足 5 分钟验收指标。需要分别采集空闲 5 分钟、连续画手势、快速复制、打开 200 条历史时的 CPU、私有内存、工作集、句柄、钩子回调 p99 和 UI 搜索延迟。

已确认的优化候选按收益排序：

1. 历史搜索改为后台查询或限时防抖，并让数据库按类型/来源先过滤；缩略图按可见行加载。当前 `storage::list_filtered` 读取全部行并解码文本/缩略图后在 Rust 中筛词，`app::rebuild_history_with_selection` 在 UI 线程同步调用它。
2. 剪贴板更新通道增加“已有待处理事件”原子门控或有界合并，避免突发复制形成无界队列；保持序号检查，不能遗漏最后一份内容。
3. 轨迹层消息改用有界批量/复用缓冲，减少绘制时的分配；先测钩子 p99，避免为不可见的微优化牺牲可靠性。
4. 钩子 30 秒重装是兼容性保险，不应在缺少真实长期对照测试前直接删除；先记录重装次数、安装失败率与原因，再评估是否调节策略。

## 建议排期

| 优先级 / 阶段 | 工作 | 完成判据 |
| --- | --- | --- |
| P0 · 0.14.2 收尾 | 用实体鼠标在两个虚拟桌面分别验证 ←/→、普通右键、任务栏右键和注入过滤；检查运行 30 分钟后托盘与钩子；包装便携版 | 双向切换实际发生并可切回；普通右键仅一次；无重放循环、无意外退出；发布记录注明结果 |
| P0 · 0.15 稳定性 | 将按下/移动/释放/注入事件抽成纯状态机；动作后端可替换；增加目标窗口变化与 Shell 快捷键确认测试；启动健康检查区分任务成功、进程存在和钩子有效 | HOK-001～003/008 与 ACT-006 能自动回归；日志可定位“识别、动作注入、系统未响应”三层 |
| P1 · 0.15 历史响应 | 后台筛选、防抖/请求代号、SQL 预筛选、可见缩略图懒加载；剪贴板事件合并 | 200 条历史搜索不阻塞 UI；突发复制不积压；置顶/筛选/高亮/自动粘贴回归通过 |
| P1 · 0.16 结构 | 从 `app.rs` 拆出历史和设置窗口控制器/视图模型，统一跨线程消息所有权；补 DPI/主题组件自动化 | 主消息过程只保留生命周期与路由，业务状态能独立测试；无资源/窗口句柄泄漏 |
| P2 · 0.16 体验 | 评估快捷操作配置的导入/导出、纯文本粘贴、忽略下一次复制等轻量能力 | 不破坏既有手势、剪贴板隐私和低常驻开销；先验证实际使用频率再排优先级 |
| 延后 · 1.0+ | 安装器、代码签名、更新机制、更多格式或插件/脚本 | 仅在稳定性、兼容性、性能指标长期达标后决策；插件/脚本需要单独安全设计 |

本轮不建议盲目替换 UI 框架或增加后台服务：现有原生界面已可用，当前最影响体验的是手势可靠性、启动健康可见性和历史搜索的最坏延迟。
