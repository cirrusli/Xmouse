# Xmouse 持续回归测试计划

> 基线版本：0.13.3
>
> 建立日期：2026-08-24
>
> 维护规则：任何用户可见行为、兼容性修复或数据格式变化，都必须在本文件新增或更新一个稳定编号。

## 1. 目标与门禁

本计划防止后续功能修改破坏已经可用的手势、系统右键、剪贴板历史和低资源特性。测试覆盖由三部分组成，三者不能互相替代：

1. **自动化测试**：纯算法、配置迁移、存储和可抽离的状态判断。
2. **真实 Windows 回归**：低级鼠标钩子、任务栏、焦点、DWM、剪贴板和 DPI 等系统交互。
3. **性能与交付回归**：空闲资源、便携包、升级和单实例。

当前硬门禁：

- 常规 Rust 测试不得少于 **42 项**，交互式真实剪贴板测试不得少于 **1 项**。
- 首次 Windows MSVC CI 实测行覆盖率为 **25.44%（1933/7597）**，函数覆盖率为 **39.06%（182/466）**。CI 将 **24%** 设为防回退线，为编译器插桩差异保留少量余量；后续只能提高，不得静默降低。
- P0 项必须有自动化测试，或明确列入每次发布的真实 Windows 必测集；不能留空。
- 修复线上回归时，先增加能复现问题的测试或稳定人工步骤，再修改实现。
- 删除测试、降低阈值或把失败测试改为忽略，必须在变更说明中单独解释。

运行标准质量门禁：

```powershell
./scripts/quality.ps1
```

剪贴板相关改动额外运行：

```powershell
./scripts/quality.ps1 -ClipboardRoundTrip
```

安装 `cargo-llvm-cov` 和 Rust `llvm-tools-preview` 后，可运行 `./scripts/quality.ps1 -Coverage`。本机 GNU 工具链若不包含 profiling runtime，以 GitHub Actions 的 MSVC 覆盖报告为准。

## 2. 每次变更的固定流程

1. 开始修改前，根据第 4 节找到受影响的回归编号。
2. 新行为至少增加一个测试；系统交互无法稳定单测时，补充一个可重复人工步骤。
3. 完成后运行 42 项常规测试、格式检查和 Clippy。
4. 执行“每次提交冒烟集”；再执行受影响模块的全部编号。
5. 发布前执行“发布必测集”、性能采样和便携包冷启动。
6. 在 PR、提交说明或版本说明中记录：回归编号、结果、系统版本、是否存在未覆盖边界。

## 11. 后续自动化补强顺序

1. 把右键按下、移动、释放、注入事件抽成纯 `GestureSession` 状态机，覆盖 HOK-001～003、006、008、010。
2. 为动作执行增加可替换 Win32 后端，记录而不真实发送按键，覆盖 ACT-001～010。
3. 抽离历史弹窗的筛选、选择、关闭和自动粘贴目标为 ViewModel，覆盖 CLP-012、014 和 UI-005。
4. 为原子配置保存、容量限制、剪贴板禁止标记补充故障注入测试。
5. 覆盖率达到新台阶后只提高门禁，不允许回调；目标为 0.14 ≥ 28%、0.15 ≥ 35%。
